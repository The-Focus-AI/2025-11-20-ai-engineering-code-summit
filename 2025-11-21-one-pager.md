# AI Engineering Code Summit - Day 2 One-Pager
## November 21, 2025

**AI makes coding dangerously easy, but easy isn't simple. Success requires augmenting human thinking through context management, prompt tuning, and verification-first design—not outsourcing architectural decisions to models.**

## The Core Problem

Jake Nations (Netflix) shipped code he didn't understand. Dex Horthy surveyed 100,000 developers stuck in endless rework cycles "fixing the slop from last week." The trap: AI makes generating code trivially easy while systems become incomprehensibly complex. Technical debt doesn't register as debt to AI—it just registers as code. Rich Hickey's warning applies: **easy doesn't equal simple**. The hard part was never typing; it was knowing what to type. We're building incomprehensibility at scale.

## Three Techniques for Augmented Thinking

**Context Management:** Beyond 40% context utilization, AI quality collapses. Netflix's approach to 5M lines: pre-research everything (architecture, design docs, Slack threads) → compress into focused markdown → plan with exact specs → implement. Subagents exist for context isolation, not capability compensation. Design phase-based workflows with human checkpoints.

**Prompt Tuning:** Aparna Dhinakaran (Arize) achieved +6-15% improvements using 150 examples through continual system-prompt learning. Use LLM evals to understand WHY agents fail, encode that learning into meta-prompts, require explanations from judge LLMs for actionable feedback. This bridges accessible prompt engineering with powerful RL, encoding organizational expertise into agent behavior.

**Verification-First:** The tea kettle principle—good verifiers test outcomes (is it whistling?), not process (is burner on high?). Dex Horthy calls this "hardness engineering": deliberately make AI's job harder by forcing human thinking upfront. Design the outcome verifier first, then build the task.

## Key Infrastructure Insights

**Environments as universal abstraction:** Starting state + harness + verifier unifies benchmarks (measure), RL training (improve), Skills (progressive knowledge), and artifacts (interactive verification). Will Brown: "Environments are the webapps of research."

**Spectrum of specialization:** Continual prompt learning (150 examples) → ARFT (1,000 examples, 10-point improvements) → Pipeline RL (fast, cheap, predictable) → Code World Models (execution-aware). Mako's GPU agent: 72% gains over frontier models with 100 examples. Pattern: smart models for planning, fast specialized models for execution.

**Data is the new bottleneck:** Nik Pash's "truth nuke"—production agents collect goldmine data but keep it locked, choking research. Models improve when trained on hard problems. The constraint isn't compute or engineering; it's collecting quality training data and having courage to share it. Cline-bench represents culture shift: data sharing as infrastructure, not competitive loss.

## What To Do

- **Never outsource thinking:** Use AI for research/implementation, humans for architecture; checkpoint at phase boundaries; treat AI "agreeing with everything" as red flag
- **Implement prompt tuning:** Collect feedback from PRs/reviews; use LLM evals to understand failures; encode learning into meta-prompts; start with 100-150 examples
- **Engineer context:** Pre-research comprehensively; compress to markdown; use subagents for domain isolation; monitor and compress when approaching 40% utilization
- **Design verification-first:** Define outcome verifiers before coding; test results not methods; invest in eval engineering as heavily as model selection
- **Explore specialization:** Map high-value tasks to right technique (prompt tuning → ARFT → RL); experiment with dual-model architectures
- **Open your data:** If running production agents, implement opt-in collection; contribute to open benchmarks; recognize collective progress beats proprietary moats
